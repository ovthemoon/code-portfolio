# 실시간 벽은 읽기 전용 연결 하나로, 끊기면 느린 조회로 대신한다

출처: 밴드 팬 사이트의 실시간 한마디 벽(외주) (wall-feed.js, worker.js, 2026-09)

## 문제
관객이 쓴 글이 다른 관객의 화면에 바로 보여야 한다. 화면마다 서버에 계속 묻는 방식은 요청이 접속자와 시간에 비례해 늘어난다. 연결은 끊길 수 있고, 탭이 숨겨졌거나 오프라인인 동안에는 아무것도 하지 않아야 한다.

## 해결
- 받기만 하는 WebSocket 하나로 스냅샷을 밀어 준다. 글쓰기는 이 연결로 받지 않고 별도의 HTTP 경로 하나로 모은다. 서버는 wall 소켓이 보낸 메시지를 모두 닫기 사유로 본다 (발췌).
- 스냅샷은 `revision`이 현재 이상일 때만 반영한다. 형식이 틀린 메시지와 더 오래된 스냅샷은 버린다 (`isAcceptableSnapshot`).
- 연결이 끊기면 지수 백오프에 20% 지터를 더해 다시 붙는다. 소켓이 첫 스냅샷을 주기 전에는 4초 뒤부터 HTTP로 대신 가져오고, 소켓이 살아나면 HTTP 요청을 취소한다. HTTP도 실패하면 조회 간격을 30초에서 120초까지 늘린다.
- 탭이 숨겨지거나 오프라인이 되면 소켓, 타이머, 진행 중인 HTTP 요청을 모두 정리하고 아무것도 보내지 않는다. 다시 보이면 이어 붙는다.
- 하트비트는 고정 문자열이라 서버 플랫폼이 객체를 깨우지 않고 답한다. 답이 없으면 연결을 끊고 다시 붙는다.

## 코드
- `wall-feed.mjs`: 클라이언트 연결 로직. 브라우저 API는 `env`로 받는다
- `wall-feed.test.mjs`: 가짜 WebSocket, 가짜 타이머, 가짜 fetch로 위 동작을 확인
- `fake-env.mjs`: 테스트용 가짜 환경
- `excerpt/wall-hub.js`: 서버 쪽 읽기 전용 소켓, 연결 상한, 방송 발췌

## 확인
```
cd js/realtime-wall-feed && node --test
```
`excerpt/`는 발췌만 있다 (Cloudflare Durable Object 런타임 전용이라 실행하지 않는다). 실제 브라우저와 서버로 재연결을 시험한 결과는 이 폴더에 없다.

## 원본과 다른 점
- 브라우저 전역(`document`, `navigator`, `WebSocket`, `fetch`, 타이머)을 직접 쓰던 것을 `env` 인자로 바꿨다. 기본값 `browserEnv()`는 같은 전역을 쓴다.
- 소켓 객체에 `received` 속성을 붙이던 것을 클로저 변수로 바꿨다.
- 스냅샷에서 공연 목록(`shows`) 필드 검사를 뺐다.
- 상태 문구를 `STATUS` 코드로 바꿨다. 주소 경로는 일반 이름이다.
- 서버 발췌의 연결 상한(`MAX_WALL_SOCKETS`)은 예시값이다. 허용 출처는 환경변수 이름으로만 남겼다.
