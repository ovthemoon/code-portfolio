# 끊겼다 다시 붙어도 같은 요청이 두 번 처리되지 않게

출처: 교실 실시간 그림 릴레이 게임(외주) (game.mjs, room-connection.js, 2026-09)

## 문제
교실 와이파이와 휴대폰 연결은 자주 끊긴다. 응답을 못 받아 다시 보낸 요청 때문에 점수가 두 번 오르거나, 이미 지나간 단계의 요청이 뒤늦게 받아들여지면 안 됐다.

## 해결
- 클라이언트가 요청마다 id를 붙인다. 서버는 (보는 사람 종류, 번호, id)를 키로 처리 기록을 남기고, 같은 키가 다시 오면 아무것도 하지 않고 성공으로 답한다.
- 기록 확인을 단계 확인보다 먼저 한다. 이미 처리된 요청을 다시 보내면 409가 아니라 성공이다.
- 처음 보는 id여도 요청에 담긴 stage와 roundId가 서버의 현재 값과 다르면 409로 거절한다. 응답을 놓친 뒤 새 id로 다시 눌러도 이중 반영되지 않는다.
- 거절된 요청은 기록하지 않는다. 처리 기록은 1000개까지만 두고 오래된 것부터 잊는다.
- 클라이언트는 요청별로 대기 목록(pending)과 타임아웃을 둔다. 연결이 끊기면 대기 중이던 요청을 모두 거절하고, 재연결 뒤에 자동으로 다시 보내지 않는다. 재연결 간격은 지수 백오프에 지터를 더한다.

## 코드
- `room-actions.mjs`: 서버 쪽 `act()`. 요청 키, 처리 기록, 단계와 roundId 검사
- `room-connection.mjs`: 클라이언트 쪽 연결. pending, 타임아웃, 끊김 시 거절, 백오프
- `room-actions.test.mjs`, `room-connection.test.mjs`: 위 두 파일의 테스트

## 확인
```
cd js/idempotent-room-actions && node --test
```
가짜 소켓과 가짜 타이머로 확인한다. 실제 기기에서 끊김을 재현한 것은 아니다.

## 원본과 다른 점
- 게임 규칙(점수 계산, 역할 이름, 단계 이름)을 일반화했다. 여기서는 제출, 점수 부여, 다음 라운드, 종료 네 가지 동작만 둔다.
- 원본은 room 객체를 제자리에서 바꾼다. 여기서는 새 room을 돌려주고 이전 값은 바꾸지 않는다. 같은 id가 다시 오면 `{ room, replayed: true }`를 돌려준다.
- 클라이언트에서 하트비트, 탭 숨김, 온라인과 오프라인 처리를 뺐다.
- 오류 문구는 짧은 일반 문구로 바꿨다.
