# 로그인 없는 한마디 벽에서 같은 제출이 두 번 들어가지 않게

출처: 밴드 팬 사이트의 실시간 한마디 벽(외주) (wall-store.js, wall.js, worker.js, 2026-09)

## 문제
누구나 로그인 없이 글을 남기는 벽이라, 버튼을 두 번 누르거나 네트워크 재시도가 겹치면 같은 글이 두 번 들어갈 수 있다. 짧은 시간에 연달아 쓰는 사람도 늦춰야 한다. 글 내용이 같다는 이유로 막지는 않는다. 같은 말을 일부러 다시 쓰는 것은 막을 일이 아니고, 같은 "제출"이 두 번 들어가는 것만 막는다.

## 해결
- 제출마다 요청 ID를 붙인다. 서버는 처리한 ID를 영수증으로 남기고, 같은 작성자가 같은 ID를 다시 보내면 글을 더하지 않고 `repeated: true`로 답한다. 이때 제한 횟수도 쓰지 않고 방송도 하지 않는다.
- 다른 작성자가 남의 ID를 쓰면 409로 거절한다.
- 작성자(익명 쿠키의 해시)에는 횟수와 간격 제한을, IP 해시에는 횟수 제한만 둔다. 한 요청이 여러 검사를 통과해야 하고, 중간에 하나라도 걸리면 어떤 카운터도 남기지 않는다.
- 벽은 최대 200장이다. 가득 차면 가장 오래된 글을 지우고 그 글의 슬롯(화면 위치)에 새 글을 놓는다. 지워진 글의 영수증은 남아 있어서, 지워진 글의 재전송이 다른 글을 밀어내지 않는다.
- 신고는 작성자마다 한 번만 센다. 바로 지우지 않고 관리자 화면에 신고 수만 보여 준다. 삭제는 글과 신고를 함께 지운다.
- 클라이언트는 페이지를 열 때 요청 ID를 만들고, 입력이 바뀌면 새 ID로 바꾼다. 제출 중에는 입력을 잠그고, 실패하면 초안과 같은 ID를 그대로 둬서 다시 눌러도 같은 제출이 된다 (발췌).

## 코드
- `note-store.mjs`: 메모리 저장소. `add`, `report`, `remove`, `snapshot`, `admin`
- `note-store.test.mjs`: 위 동작의 테스트
- `excerpt/note-form.js`: 요청 ID 발급, 입력이 바뀌면 새 ID, 제출 중 잠금 (브라우저 폼 코드 발췌)
- `excerpt/note-route.js`: 쓰기 경로. 트랜잭션 안에서 `add`, 반복이면 방송 생략 (Durable Object 코드 발췌)

## 확인
```
cd js/note-submit-receipts && node --test
```
`excerpt/`는 발췌만 있다 (브라우저와 Durable Object 전용이라 실행하지 않는다).

## 원본과 다른 점
- 원본은 Durable Object의 SQLite 테이블에 저장한다. 여기서는 메모리 저장소로 다시 만들었다. 원본에서 트랜잭션이 맡던 원자성은, 다음 상태를 새로 계산한 뒤 예외 없이 끝났을 때만 바꿔 놓는 방식으로 대신한다. 상태는 제자리에서 바꾸지 않는다.
- 제한 숫자(`MAX_NOTES_PER_AUTHOR`, `MIN_GAP_PER_AUTHOR_MS`, `MAX_NOTES_PER_IP`, `MAX_REPORTS_PER_IP`, `MIN_REPORT_GAP_MS`)와 제한 창, 영수증 보관 시간(`LIMIT_WINDOW_MS`, `RECEIPT_TTL_MS`)은 예시값이다. 상한 200장과 글자 수 제한(50자, 닉네임 12자)은 원본 값이다.
- 공연 선택, 날짜와 장소 복사, 포스트잇 색 필드를 뺐다. 한국어 문구는 일반 문구로 바꿨다.
- 신고 요청의 IP 제한은 원본에서 라우트가 부르던 것을 `report`가 직접 적용한다.
- 없는 글을 `remove`하면 원본은 revision을 올리고 방송했다. 여기서는 바뀐 것이 없으면 revision을 올리지 않는다.
- 영수증이 만료됐는데 같은 ID의 글이 아직 벽에 있으면 409로 거절한다. 원본에서는 DB의 UNIQUE 제약이 이 경우를 막는다.
