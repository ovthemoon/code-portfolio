# PC가 꺼져 있던 동안 지난 반복 업무 회차를 기록 없이 버리지 않는다

출처: OpenDesk (cron_missed.py, 2026-09)

## 문제
"매일 아침 메일 정리" 같은 반복 업무는 PC가 꺼져 있으면 그냥 사라졌다. 메모리 스케줄러는 기동 이전의 슬롯을 발화하지 않고, 종전 따라잡기는 자는 동안 지난 슬롯을 기록도 없이 버렸다. 사용자는 업무가 돌지 않았다는 사실조차 알 수 없었다.

## 해결
- 데몬이 "살아 있음" 시각을 파일에 남긴다(`last_alive`).
- 부팅하면 그 시각을 읽고, 계획을 세운 뒤에 마커를 새로 쓴다. 쓰기를 먼저 하면 기준선이 지금으로 덮인다.
- (마지막 생존 시각, 지금] 창의 슬롯을 세어, 허용 시간 안이면 실행하고 지났으면 "자는 동안 놓침"으로 기록한다. 허용 시간은 주기의 절반이고 하한과 상한이 있다.
- 깨어난 직후 한꺼번에 몰리지 않도록 실행 개수에 상한을 둔다. 넘는 것은 오래된 슬롯이 실행에 남고 나머지는 기록으로 돌린다.
- 이미 발화한 슬롯은 건너뛴다. 마커가 한 주기 낡아도 중복 기록이 생기지 않는다.
- 마커가 깨졌거나 없으면 기준선 없음으로 보고 부팅을 막지 않는다.
- 분 단위 업무도 탐색이 유계가 되도록, 최근 슬롯은 작은 창부터 넓혀 가며 찾고 슬롯 수는 상한에서 멈춘다.

## 코드
- `missed_schedule.py`: 마커 읽기와 쓰기, `_plan_one`, `plan_missed`와 필요한 자료형. 부팅 흐름(`plan_at_boot`)과 스케줄 두 종류는 새로 썼다.
- `test_missed_schedule.py`: 여러 슬롯, 허용 시간, 전달 보장 방식, 이미 발화한 슬롯, 한 번짜리 업무, 몰아치기 상한, 탐색 상한, 마커 손상, 부팅 순서 테스트.

## 확인
```
cd python && python3 -m pytest missed-schedule-recovery
```

## 숫자와 조건
- 되돌아보는 최대 기간 7일, 몰아치기 기본 상한 5개, 슬롯 탐색 상한 2000, 허용 시간 하한 120초와 상한 7200초는 원본 코드의 값이다.
- 코드와 테스트만 확인했다. 실사용 횟수는 없다.

## 원본과 다른 점
- 원본은 APScheduler의 cron 트리거를 쓴다. 여기서는 표준 라이브러리만 쓰도록 매일 한 번(`DailySchedule`)과 고정 간격(`IntervalSchedule`) 스케줄로 바꿨다.
- 업무 자료형은 이 계획에 필요한 필드만 남기고 이름을 일반화했다.
- 이사 번들에서 기준선을 가져오는 경로, 마커를 주기적으로 쓰는 루프, 계획을 실행하고 원장에 기록하는 부분은 가져오지 않았다. 계획까지만 있다.
- 마커 파일 쓰기는 원본의 경로 모듈 대신 임시 파일과 `os.replace`로 직접 구현했다.
