# 끊긴 연결에 걸린 도구 호출을 시간 제한으로 끊고, 읽기 호출만 한 번 다시 한다

출처: OpenDesk (mcp_retry.py, mcp_client.py, 2026-08, 2026-11)

## 문제
AI 동료가 외부 도구(MCP)를 부르면 가끔 대답 없이 멈췄다. 원격이 유휴 연결을 끊었는데 데몬은 그걸 모르고 응답을 기다렸다(소켓 CLOSE_WAIT로 확인). 도구 호출에는 시간 제한이 없었고, 턴이 끝나지 않았다.
시간 제한만 걸면 새 문제가 생긴다. 타임아웃 뒤 다시 호출하면 원격이 이미 처리한 작업이 한 번 더 실행될 수 있다. 메일 보내기라면 두 통이 나간다.

## 해결
- 호출에 시간 제한을 두고, 시간이 지나면 그 서버의 세션을 버린다. 다음 호출은 새로 연결한다.
- 재시도는 읽기로 확인된 호출만 한 번 한다. 도구가 `readOnlyHint`를 단 것만으로는 부족하고, 호스트가 신뢰한 서버이면서 이름의 동사와 인자가 읽기와 모순되지 않아야 한다.
- 재시도 권한은 호출이 시작될 때 호스트가 `ContextVar`에 넣어 둔 스냅샷이다. 정책을 끄거나 도구별 override를 넣어도 평가 스위치는 모두 켠 채로 굳힌다. 스냅샷이 없으면 권한도 없다.
- 다시 연결한 뒤 서버 이름, 도구 이름, 입력 스키마를 호출 전과 비교하고, 읽기 평가를 한 번 더 한다. 하나라도 다르면 재시도하지 않는다. 도구 목록을 새로 받지 못한 경우도 마찬가지다.

## 코드
- `read_retry_policy.py`: 재시도 권한 스냅샷과 판정. 원본 `mcp_retry.py` 전체를 일반 이름으로 옮겼다.
- `call_assessment.py`: 읽기 여부를 판정하는 최소 평가기. 원본은 별도 패키지의 긴 규칙 집합이라 재시도에 필요한 부분만 새로 썼다.
- `resilient_tool_hub.py`: 시간 제한, 세션 폐기, 계약 비교와 한 번 재시도. 원본 호출 경로를 asyncio로 줄여 다시 만들었다.
- `test_read_retry_policy.py`, `test_resilient_tool_hub.py`: 권한 판정과 호출 경로 테스트.

## 확인
```
cd python && python3 -m pytest mcp-read-only-retry
```

## 숫자와 조건
- 시간 제한 상한은 60초다(2026-08 커밋 기준). 테스트는 짧은 제한을 주입해 쓴다.
- 장애 발생 빈도는 측정하지 않았다.

## 원본과 다른 점
- 정책 필드와 컨텍스트 변수 이름을 일반화했다(`trusted_origins`, `read_verified_origins`).
- 읽기 평가기는 원본의 규칙 집합이 아니라 이 사례에 필요한 판단만 담은 재구성이다. 전각 문자와 제로폭 문자로 동사 검사를 피하지 못하게 하는 정규화는 유지했다.
- 허브는 원본의 인증 실패 경합, 지연 연결, 로깅을 뺐다. 결과는 문자열 대신 `ToolResult`로 돌려준다.
- 원본 토크나이저는 camelCase를 나누지 않았다. 여기서는 나눈다(`sendEmail`은 `send`와 `email`).
