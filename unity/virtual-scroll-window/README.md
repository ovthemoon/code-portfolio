# 우편 1,000개에서 스크롤이 20 FPS로 떨어지던 목록

출처: 무림 히어로즈 (MailBoxPopup.cs, 2026-10)

## 문제
우편함에 우편 1,000개를 만들면 행 1,000개를 모두 생성해 첫 배치가 오래 걸렸고, 스크롤은 약 20 FPS까지 떨어졌다.

## 해결
화면에 걸치는 행과 위아래 여분(overscan) 행만 만들고, 벗어난 행은 풀로 돌려 재사용한다.
- 스크롤 위치와 뷰포트 높이로 보이는 구간 `[first, end)`를 계산한다. 위치가 내용 밖이어도 구간이 항목 범위를 벗어나지 않는다.
- 현재 만들어 둔 행과 새 구간을 비교해, 돌려보낼 행과 새로 꺼낼 행만 구한다. 결과 리스트는 재사용해 스크롤 중 할당을 만들지 않는다.
- 행 높이가 고정이 아니거나 레이아웃이 예상과 다르면 가상 스크롤을 켜지 않고 일반 목록으로 남긴다.

## 코드
- `VirtualListLayout.cs`: 행 배치, 내용 높이, 스크롤 클램프, 보이는 구간 계산
- `VisibleRowDiff.cs`: 풀로 돌려보낼 행과 새로 꺼낼 행 계산
- `Tests/`: 구간 경계, 범위 이탈, 보이는 행 누락 없음, 1,000개를 끝까지 스크롤해도 만든 행이 창 크기에 묶이는지
- `excerpt/MailBoxPopup.VirtualList.cs`: 원본 발췌. Unity UI 컴포넌트에 의존한다.

## 확인
```
cd unity && dotnet test
```
`excerpt/`는 발췌만 있다(원본은 Unity 의존). 빌드에서 제외된다.

## 숫자와 조건
Android 에뮬레이터, 우편 1,000개, 전후 각 3회 측정의 중앙값(2026-10-04).
- 스크롤: 20.43 FPS에서 59.47 FPS
- 첫 배치: 458.50ms에서 82.83ms
- 처음 만드는 행: 1,000개에서 6개
- 실기기 값이 아니다. 이 폴더의 테스트는 위 측정을 재현하지 않는다.

## 원본과 다른 점
- 보이는 구간 계산을 Unity UI 컴포넌트(RectTransform, ScrollRect)에서 떼어 순수 함수로 다시 썼다. 원본의 floor, ceil, overscan, 클램프 식은 그대로다.
- 원본은 실제 내용 높이를 컴포넌트에서 읽고, 여기서는 항목 수로 계산한다.
- 행 간격이 0 이하이면 예외를 던진다. 원본은 같은 조건에서 가상 스크롤을 켜지 않았다.
- 행 풀, 행 초기화, 위치 지정 등 UI 코드는 발췌 파일에만 있다.
