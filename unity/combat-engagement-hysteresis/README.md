# 적 앞을 오가기만 하고 공격하지 않던 자동 전투 AI

출처: 무림 히어로즈 (HeroEngagementRules.cs, HeroAttackPlanner.cs, HeroSpacingRules.cs, 2026-10)

## 문제
자동 전투에서 영웅이 공격하지 않고 적 앞을 오가기만 했다. 대기, 접근, 전투 상태가 사거리를 각자 다른 우선순위와 폴백으로 계산했고, 사거리 경계에서 매 프레임 상태가 뒤집혔다. 전원이 가장 가까운 적만 고르는 문제도 같이 있어 한 적에 영웅이 몰렸다.

## 해결
- 다음 공격과 사거리를 정하는 곳을 하나로 합쳤다. 궁극기, 액티브, 기본공격 순이고, 사거리가 비어 있는 스킬은 스탯 사거리가 아니라 기본공격 사거리를 따른다.
- 접근에서 전투로 들어가는 선(사거리보다 조금 안쪽)과 전투에서 접근으로 돌아가는 선(사거리 밖)을 다르게 뒀다. 사이 구간에서는 현재 상태를 유지한다.
- 시전 조건이 안 맞는 궁극기에 묶여 기본공격도 안 하던 것을 막으려고, 궁극기는 시전 가능 여부까지 보고 준비 상태를 정한다.
- 표적 점수에 이미 그 적을 노리는 동료 수를 벌점으로 더했다.

## 코드
- `HeroEngagementRules.cs`: 공격 계획과 진입, 이탈 경계선 규칙
- `HeroAttackPlanner.cs`: 스킬 상태를 규칙에 넣어 계획을 얻는 단일 진입점
- `HeroSpacingRules.cs`: 표적 점수
- `Tests/`: 규칙 단위 테스트와, 경계에서 흔들리는 거리 열로 상태 전환 횟수를 세는 테스트

## 확인
```
cd unity && dotnet test
```

## 숫자와 조건
원본 게임 플레이 기록(상태 전이와 위치 기록기, 2분, 영웅 5명) 기준이고, 수정 전후를 같은 방식으로 쟀다.
- 접근과 전투 왕복: 영웅 한 명이 2분 동안 160회에서 0회
- 셋 이상이 한 적에 몰린 시간 비율: 68%(전원이 가장 가까운 적만 고르던 때)에서 9%
- 9%는 고를 적이 셋 이상일 때의 값이다.
- 이 폴더의 테스트는 위 측정을 재현하지 않고 규칙만 검증한다.

## 원본과 다른 점
- Unity 의존(Mathf, 스킬 객체, 스킬 컨트롤러)을 걷어냈다. 계획기는 스킬 객체 대신 값 스냅샷을 받는다.
- 표적 점수 외의 간격 유지와 진형 추종은 Unity 벡터에 의존해 뺐다.
- 주석의 캐릭터 이름과 측정값을 지웠고, 테스트의 사거리는 일반 값으로 바꿨다.
- 경계 흔들림 비교와 표적 분산 테스트는 이 레포에서 새로 썼다.
