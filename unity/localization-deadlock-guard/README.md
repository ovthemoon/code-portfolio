# 동료 만들기 화면에 들어가면 매번 멈추던 번역 데이터 대기 교착

출처: OpenDesk (WizardLoc.cs, LocTablePreloader.cs, 2026-08)

## 문제
0.5.0 빌드의 Windows PC에서 동료 만들기 화면에 들어가면 앱이 매번 응답하지 않았다. 처음에는 화면 진입 한 프레임에 캐릭터 약 30개를 동기 생성하는 것이 원인이라 보고 지연 생성으로 고쳤지만 멈춤이 남았다. 진입 경로에 기록을 남겨 보니 멈춘 곳은 번역 조회였다. 아직 불러오지 않은 번역 표를 동기로 조회하면 내부에서 표를 동기 로드하며 대기하는데, 메인 스레드가 자기 완료 콜백을 기다리는 교착이 된다.

## 해결
- 화면에 들어가기 전에 필요한 번역 표를 비동기로 미리 불러온다(`LocTablePreloader`). 비동기 로드는 교착하지 않는다.
- 조회 함수는 표가 이미 로드됐을 때만 읽고, 아니면 로드를 시작만 한 채 키를 그대로 돌려준다(`WizardLoc.T`). 진입점이 미리 불러오기를 빠뜨려도 최악이 글자 대신 키가 보이는 것이고, 교착은 구조상 일어나지 않는다.
- 미리 불러오기 실패는 진입을 막지 않는다. 경고만 남기고 조회는 키 반환으로 흐른다.

## 코드
- `excerpt/WizardLoc.cs`: 로드된 표만 읽고 아니면 키를 돌려주는 조회 함수
- `excerpt/LocTablePreloader.cs`: 진입 전에 번역 표를 비동기로 불러오는 함수

## 확인
발췌만 (원본은 Unity Localization 패키지와 UniTask 의존).

## 숫자와 조건
Windows 1대, 0.5.0 빌드에서 확인했다. 수정 전에는 화면 진입 때마다 멈췄고, 수정 후에는 정상 진입했다. 다른 기기와 사용자 비율은 측정하지 않았다.

## 원본과 다른 점
- 두 파일에서 해당 함수만 발췌했다. `WizardLoc`의 초기화 확인 속성, 포맷 함수와 `LocTablePreloader`의 클래스 설명 주석은 생략했다.
- namespace와 using을 걷어 내고 주석을 정리했다.
